# Verifier evaluation

Reproduce with `npm run eval`, which runs the real verifier with the MiniLM model. `TRUSTRAIL_EMBEDDER=lexical npm run eval` runs the no-AI baseline.
Cases: `eval/cases.json`, generated by `eval/make-cases.py`. Results: `eval/results-*.json`.

**What counts as a false approval:** the verifier **captures** payment for a delivery labeled `reject`.
"Escalate" sends the case to a human. It never moves money on its own, so we count it as safe but costly.

| | MiniLM + deterministic checks (default) | Lexical baseline (no AI) |
|---|---|---|
| Cases (normal / adversarial) | 7 / 18 | same |
| **False approvals** | **0/18** | 0/18 |
| Good briefs auto-captured | 4/7 | 0/7 |
| Good briefs sent to a human | 3/7 | 7/7 |
| Good briefs wrongly voided | 0/7 | 0/7 |
| Held-out (written after tuning): false approvals / good captured | 0/3 · 0/2 | |

## Caveats (please read)
- **This set is small and we wrote it ourselves**: 25 cases over 2 brief specs. The answer-type check, the topic-anchor check and the "echo" threshold were all added after we saw failures on the first 20 cases. Those 20 are a dev set, not a test.
- On the 5 held-out cases there were 0 false approvals. Both held-out good briefs were escalated, because they are under the order's 150-word minimum, so the length check failed as specified.
- **The semantic layer alone was not enough.** Before the deterministic answer-type and topic-anchor checks, MiniLM similarity approved **4/15** adversarial deliveries: partial answers, the GDPR-instead-of-AI-Act brief, and an off-topic one. Embedding similarity measures relatedness, not whether a question was answered. That is why the final decision combines several signals and leans toward escalating to a human.
- **Keyword stuffing scores higher than real answers.** Passages that restate the question score 0.87–0.95 cosine, while genuine answers score 0.55–0.78. The verifier therefore treats a score of 0.85 or more as "uncertain (echo)" and never auto-passes it.

## LLM judge: what we tried
- The verifier has a pluggable LLM judge (`src/ai/judge.js`): any OpenAI-compatible endpoint, or a local model. Its output is schema-checked. It can veto or downgrade a verdict, but it can never approve something retrieval rejected.
- **Free local option we tested:** Qwen2.5-0.5B-Instruct (Apache-2.0, via transformers.js, $0, offline). In a direct probe it answered "pass" for a correct passage, a passage that only restated the question, and a GDPR passage given for an AI Act question. Its JSON also often used the wrong keys, which the schema check turns into "uncertain". Net effect: it sent every good brief to a human and added no discrimination. **It is therefore off by default** (`TRUSTRAIL_JUDGE=local` turns it on).
- We did not test a larger hosted model, because that would need a paid or keyed API and this project spends $0. The interface is ready for one (`AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`). **No LLM output in this repo or in the demo is simulated.**
